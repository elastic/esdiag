## Context

See [proposal.md](proposal.md) for motivation. `src/receiver/archive/scrub.rs` currently has `normalize_value` for raw `String` (parse whole input as `serde_json::Value`, recurse, serialize), and `normalize_json_stream` with a separate hand-maintained token/context stack for typed/streamed reads. Both call the already-shared `normalize_string_for_field` and IPv4 helpers; the duplication is **field-scope traversal**, not modulo or allowlist rules. File/bytes/directory raw Load uses `normalize_supported_content`; eager typed and streamed Load uses `with_normalized_json_reader` with `normalize_supported_reader_to_temp`. Existing `malformed-ip-normalization` and `streaming-deserialization` specs remain unchanged; this change opts out of a delta spec because it changes no requirement.

The current parent contract explicitly bounds enabled, supported normalization to 128 nested containers before another traversal context is allocated. This approved parent correction is inherited, not a new acceptance policy introduced by this refactor. Direct-reader bypasses and stricter consumer limits remain intact.

## Goals / Non-Goals

**Goals:**
- One private field-scope traversal owns key decoding, child-key scope, array field inheritance and string selection for both output adapters. Concentrate scope logic for locality without widening the receiver interface; the output seam is private to `scrub.rs` and has two actual adapters (raw and buffered temporary-file). Raw input retains full syntax validation without requiring the typed/streamed adapter to adopt a new acceptance policy.
- Raw output necessarily scales with output size; typed/streamed normalization memory scales with nesting and largest decoded token plus fixed buffers, not payload length or `serde_json::Value` tree. Preserve the receiver-first Load→Process order and current Job/type-state transitions; no new receiver/processor/exporter trait or transition.
- Preserve supported raw input's full JSON validation, numeric interpretation and duplicate-key semantics, while retaining the typed/streamed consumer's existing syntax, numeric and depth behavior. Propagate reader/writer errors and never return partial output as a successful normalization result.

**Non-Goals:**
- No public interface changes to `normalize_supported_content`, `with_normalized_json_reader`, receiver methods, CLI/UI scrub selection, Job executor or processor deserializers; no retries, telemetry, upload changes, customer fixtures or new dependencies.
- No generic public serializer framework, fabricated adapter for future formats, changes to allowed address names or node-lookup processing, or byte-for-byte guarantee for enabled supported raw JSON.

## Decisions

### One field-scope traversal, two output adapters, existing validation policy

Reuse the current token/context traversal as the single field-scope walk and let it emit private structural, key, string and literal events to the two concrete output adapters. Decode keys and strings with the existing Serde facilities; arrays inherit their enclosing field and object children replace that scope with their own immediate key. Keep `normalize_string_for_field` and IPv4 rules in this walk, not in either output adapter. Do not replace the token-preserving typed path with unconditional `deserialize_any`: that could canonicalize number lexemes, impose another recursion limit, or reject large numbers currently preserved for a downstream `RawValue`. Raw supported input additionally receives complete grammar validation with the existing `serde_json::Deserializer`, a private recursive discarded-value visitor and `end()`. Recursive container entry retains Serde's `Value` recursion checks before parsing later values; `IgnoredAny` is used only for string object keys, never nested values. This pass owns no address rules or Value tree and releases decoded-string scratch before raw output assembly. The raw output adapter retains Value-compatible scalar-number emission and duplicate bookkeeping. Do not expand the byte walk into another handwritten full JSON parser.

Keep the output seam private and concrete. The temporary-file adapter continues copying unchanged tokens incrementally through `BufWriter<NamedTempFile>`, rewriting only selected address strings, flushing and rewinding before the current typed/streaming consumer runs. It holds the file alive through deserialization, never accumulates full output or a Value, and leaves downstream syntax/duplicate/numeric interpretation unchanged. The raw adapter returns its final String without a temporary file; it may retain output-sized fragments and per-object key indexes to preserve last-key-wins behavior and surviving-field counts. Store fragments once and assemble final output once rather than copying whole subtrees at every nesting level. Both adapters use the same field-scope walk; delete raw `normalize_value` and do not retain a raw-only address-normalization fallback. Preserve the allowlist, port split, unbounded modulo-255 accumulator, file exclusions and debug/count intent without logging-text tests.

### Preserve different consumer interpretation without pretending byte stability

Raw supported scrubbed content currently accepts what `serde_json::from_str::<Value>` accepts: duplicate decoded object keys retain their last value, numbers follow `Value` numeric semantics, and transformation counts are derived from the surviving tree. Preserve these facts using output-fragment bookkeeping rather than a Value tree. For each object, index decoded keys to emitted child fragments and their counts; replace earlier fragments/counts on a duplicate key and assemble only the surviving values. Parse scalar numeric tokens with the existing `serde_json::Number` interpretation and serialize the accepted number, so integer/float distinctions, exponent overflow and negative-zero behavior remain compatible. Enforce the raw Value parser's container-depth acceptance during syntax validation, not after scanning the whole input. Insignificant whitespace, escape spelling and key order remain non-byte-stable for enabled supported raw content; semantic values, acceptance and surviving counts do not. Raw output-sized storage/key bookkeeping is permitted and must never leak into temporary-file normalization.

Typed/streamed content keeps the existing lexical copy path for unchanged keys, strings and number/literal tokens within the parent's 128-container normalization budget. Do not collapse duplicate keys, canonicalize numeric lexemes, impose raw `Value` scalar/depth limits, or add an unconditional root `end()` policy in this adapter; within the normalization budget, the existing typed consumer remains responsible for its own interpretation and stricter errors. Characterization tests confirm these existing contracts rather than deciding whether compatibility matters. This preserves the current temporary-file implementation while deleting a second address-field traversal, instead of substituting a new parser problem for the approved simplification.

### Selection, errors, resource ownership

Retain `supports_json_normalization` for every `.json` except `diagnostic_manifest.json` and `version.json`. Disabled/unsupported raw reads return the original String exactly, including invalid JSON; disabled/unsupported typed/streamed reads use the original reader directly without a normalization temporary file or normalization depth budget. Enabled supported raw reads perform complete validation and reject malformed/truncated JSON, trailing garbage and Value-incompatible numeric/depth cases as before. Enabled supported typed/streamed reads retain the parent's 128-container traversal budget, existing consumer acceptance within that budget, and reader I/O errors, not a new raw-validation policy. Traversal/writer failures drop partial temporary output; successful normalization flushes/rewinds and retains ownership until consumption finishes. Diagnostic reporting, owner isolation, Load placement and Job/processor transitions remain unchanged (ADR-0016, ADR-0008 and ADR-0004).

### Observable compatibility scenarios (planning cases, not a new delta spec)

- **GIVEN** a scrubbed supported `nodes.json` with malformed address strings in `ip`, `host`, `publish_host`, `bind_host`, `transport_address`, `publish_address`, `bound_address`, `local_address`, `remote_address` and `x_forwarded_for`, **WHEN** raw/typed/streamed receiver reads run, **THEN** only allowlisted address strings normalize; `ip`/`host`/pure-IP mirrors strip ports, optional-port fields keep ports, valid IPv4 remains valid, unbounded decimal octets use modulo 255, and reported counts reflect the actual transformed fields.
- **GIVEN** nested arrays under an address key, objects under an address key, escaped address keys, escaped strings and Unicode unrelated values, **WHEN** supported scrubbed content is read through the receiver seams, **THEN** every array element inherits address scope, each object child uses its own decoded key, semantic non-address values and JSON types remain unchanged, and keys/strings are correctly decoded and emitted.
- **GIVEN** malformed JSON (truncated object/string, trailing garbage, invalid literal or number) in an enabled supported raw read, **WHEN** it is loaded, **THEN** Load rejects it as before; **GIVEN** a read error during enabled supported typed/streamed Load, **WHEN** normalization runs, **THEN** the error is propagated and no partial temporary output is consumed.
- **GIVEN** raw supported input with duplicate keys (including equivalent escaped keys) and numeric boundary forms, **WHEN** scrub-enabled raw receivers read it, **THEN** acceptance, numeric values/types, last-key-wins values and surviving-field counts match existing `Value` behavior, without claiming scrub-on bytes are stable.
- **GIVEN** scrub disabled or a file outside supported `.json` (including `diagnostic_manifest.json` and `version.json`), **WHEN** raw receiver reads it, **THEN** the returned content is byte-for-byte the original String even if it is not valid JSON; typed/streamed readers retain direct deserialization without a normalization temp file.
- **GIVEN** a scrubbed Bundle loaded by CLI `process` or Web UI upload, **WHEN** a source is processed, **THEN** the receiver supplies normalized JSON before Process, preserves existing exported node outcomes and debug/count intent, and does not change the Job executor or owner-scoped diagnostic reporting.

## Risks / Trade-offs

- **Duplicate keys and numbers:** the raw `Value` path currently discards earlier duplicate keys and may canonicalize numeric forms; copying original tokens directly would be a consumer-visible incompatibility. Object-local raw fragment/index bookkeeping and Serde-compatible numeric emission are part of the design, not optional post-merge polish. Cover duplicate normalization counts and edge numeric representations at raw receiver seams before replacing the old path. Typed semantics may differ from raw by design; compare independently against existing typed consumers.
- **Validation cost:** removing a whole Value tree does not remove the raw syntax-validation work. The raw route retains a tree-free syntax pass with bounded recursive container state and largest-decoded-token scratch, then one field-scope traversal and output assembly; release validation scratch before assembly. Measure CPU and RSS against PR330 and avoid repeated fragment/subtree copying. The temporary-file route keeps its current token preservation and memory profile, including numeric and depth acceptance.
- **Resource target:** measure a synthetic large JSON Bundle with many repeated entries (no customer data), demonstrating temporary-file adapter memory grows with nesting/largest token plus buffer rather than payload; raw is separately allowed output-size plus per-object bookkeeping. Compare scrub-on versus scrub-off maximum RSS using the same fixture and binary, preserving the documented ≤20% target in `docs/scrubbed-diagnostics.md`; do not assert measurements in this planning change.
- **Lower-layer integration:** this native layer is based on typed archive consolidation and includes its shared loader. Preserve that loader and the unchanged normalization interface when propagating lower-layer fixes with a cascading stack rebase; verify both adapters on the combined implementation. Upload cleanup is the succeeding layer, not a sibling PR against main.
