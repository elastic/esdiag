# ESDiag 0.17.0 Release Notes

## New Features

- **Guided setup:** `esdiag init` walks you through your diagnostic user, output cluster, hosts, and default job, or continue in the browser at `/welcome`. (#377, #411, #412)
- **One-command local stack:** `esdiag local` starts and manages a local Elasticsearch and Kibana for analysis, running ESDiag natively without its own container.
- **Ask Agent Builder:** `esdiag agent ask` and `esdiag process --ask` open a Kibana Agent Builder conversation with your diagnostic already in context. (#379)
- **Agent Skills:** `esdiag agent skills` installs a version-matched ESDiag skill for Claude Code, Codex, and OpenCode, with no network access needed. (#379)
- **Elasticsearch Serverless:** use a Serverless project as your diagnostic cluster. (#390, #405)
- **Detail dashboards:** drill down from the overview dashboards into a single index, data stream, alias, node, or ingest pipeline. (#385, #406)
- **Lightweight collection:** download `esdiag-lite.sh` or `esdiag-lite.ps1` from this release to collect diagnostics without installing ESDiag, and forward them to Elastic Upload Service.
- **Native Windows download:** a standalone `esdiag.exe` that runs without the Visual C++ Redistributable.
- **Clearer results:** every command reports a structured outcome, including rejected documents and affected indices, so you know exactly what succeeded. (#350)

## Before You Upgrade

- CLI commands print YAML outcomes by default; use `--format json` in scripts. `process` exits nonzero when a diagnostic fails. (#350)
- Saved `jobs.yml` files migrate automatically on first read, so back them up first. (#353)
- `esdiag serve` listens on `127.0.0.1` by default; set `--bind` or `ESDIAG_BIND` to expose it.
- Direct Elasticsearch API key inputs are only available in user mode. In shared service mode, `/api/api_key`, `/api_key`, and `/api_key/{id}` return 404.
- Run `esdiag setup` against existing diagnostic clusters to apply updated mappings. (#347, #354)
- `esdiag-local up --upgrade` is now `esdiag-local upgrade`.

See [CHANGELOG.md](https://github.com/elastic/esdiag/blob/0.17/CHANGELOG.md) for the full list of changes.
