# ESDiag 0.17.0-rc1 Release Notes

Changes since 0.16.5.

## Highlights

- Guided first-run setup with `esdiag init` and a resumable web onboarding flow for diagnostic users, output deployments, collection hosts, and saved jobs.
- Native `esdiag local` lifecycle management for a local Elasticsearch and Kibana stack, with core mode running the native ESDiag binary and an explicit full-container option.
- Kibana Agent Builder integration through `esdiag agent ask` and `esdiag process --ask`, including conversation follow-ups and links back to Kibana. (#379)
- Offline, version-matched Agent Skill installation for Claude Code, Codex, and OpenCode with `esdiag agent skills`. (#379)
- Elasticsearch Serverless setup support, including compatible security and license detection, lifecycle settings, and Kibana asset installation. (#390)
- One staged diagnostic workflow across CLI, web, and synchronous APIs, with separate processed-document export and raw-bundle upload destinations.
- Lightweight collection scripts for shell and Windows PowerShell: `esdiag-lite.sh` and `esdiag-lite.ps1`.

## Compatibility And Upgrade Notes

- Finite CLI commands now emit typed YAML outcomes on stdout by default. Automation that parsed human-readable completion output must adapt to the structured result, or request `--format json`. Document streams remain NDJSON.
- `process` now exits nonzero when the derived diagnostic outcome is failed. Synchronous API responses include an `outcome` field. (#350)
- Legacy `jobs.yml` definitions migrate to the versioned, phase-based schema on first read. Back up saved configuration before upgrading; unknown source selections are preserved and reported when the job runs. (#353)
- Diagnostic application and platform identity are separate. Manifests retain compatibility, platform values use stable hyphenated keys, and setup installs compatibility aliases for older indices. Run setup against existing diagnostic deployments and review any mapping warnings. (#347, #354)
- Live collection is scoped to Elasticsearch, Kibana, and Logstash. Agent and platform diagnostics use product-provided bundles; Agent bundle processing that is not implemented is reported explicitly. (#355)
- Saved credentials are mediated by the user-mode keystore. Service outputs use runtime credentials, and ad-hoc input API keys remain transient. Secrets are redacted in debug and log output. (#352)
- Saved hosts distinguish target applications, Cloud routing, and unresolved URL templates. Legacy records receive clearer validation. (#366)
- `esdiag-local up --upgrade` is replaced by `esdiag-local upgrade`, and `esdiag local upgrade` upgrades binary-managed stacks. Both ask for confirmation unless given `--force`. New local stacks use Elastic 9.5.5; existing stacks keep their versions until upgraded.
- Agent Builder commands require the Cargo `agent` feature, which remains included in default builds. (#379)
- `elasticrc` now parses schema-keyed `ServiceConfig<T>` values into typed runtime `Service<T>` values. Its package version and publication remain independent of the ESDiag release.

## Onboarding And Local Deployments

- Configure only the collection, processing, and asset-installation stages needed for a workflow. Saved non-secret preferences supply defaults after explicit command and environment settings.
- Resume web onboarding at `/welcome`, with masked credential forms, endpoint validation, and separate Elasticsearch/Kibana asset status and reinstall actions.
- Recognize environment-provided diagnostic deployments and migrate representable legacy web output settings into shared `esdiag.yml` preferences with a backup.
- Preserve local-stack startup files after failures so credentials, retries, and shutdown remain available. Readiness checks handle authenticated services and transient Elasticsearch startup authentication failures.
- Retain `auto`, `core`, or `full` mode per local deployment. Open the onboarding page after setup completes and report native server early exits with a log path.
- Added onboarding documentation for collection, processing, local and remote diagnostic clusters, Agent Skills, and shared services.

## Collection, Processing, And Reporting

- Use canonical source-registry keys for collection and processing. Optional sources missing from imported bundles no longer make otherwise successful processing partial. (#348, #350)
- Separate API request status from local file, directory, and stream writes; local writes report the reserved status `0`. (#350)
- Report rejected documents, affected indices, and bulk rejection samples, including the destination after ingest rerouting. Failure-store redirects no longer count as successfully indexed diagnostic documents.
- Enable failure stores for new diagnostic data streams and preserve legacy provenance writers after rollover.
- Fix indexing of searchable-snapshot statistics, nested incremental-bulk settings, HTTP warning-header limits, and node transport/HTTP settings with both `type` and `type.default`.
- Fix successful Logstash diagnostics incorrectly reporting partial outcomes and avoid an extra JSON source copy during archive and directory processing.
- Replace `min-diag.sh` with version-aware `esdiag-lite.sh`, including optional ZIP output, environment-based authentication, and optional Elastic Upload Service forwarding without a jq dependency.

## Web, Dashboards, And Setup

- Isolate service-mode UI events by owner and enforce service job caps through a pluggable authentication provider. (#351)
- Keep browser uploads connected through card replacement and avoid duplicate result cards. Restore processed-document statistics and explicit serve-output behavior in the unified runner. (#380, #381)
- Honor `ESDIAG_KIBANA_SPACE`; `_default` selects the default space and unprefixed URLs. Resolve imported dashboard/data-view IDs before generating diagnostic links.
- Continue Kibana asset installation when Elasticsearch rejects some assets and report partial mapping updates with recovery guidance.
- Fix lifecycle dashboard time ranges, navigation-panel imports, case-number mappings, and an empty Search Summary visualization.
- Restrict ESDiag data views to the owned `-esdiag` stream suffix and avoid linking an unpaired output host to an unrelated Kibana viewer. (#354)

## Packaging

- Use the publicly published Elasticsearch crate with a response compatibility adapter, restoring registry-only dependency resolution for ESDiag.
- Regenerate third-party notices for the release candidate.
- Use committed notices for registry installation and package verification; source-build notice regeneration is opt-in with `ESDIAG_GENERATE_NOTICE=1`.
- Compile web onboarding only when both `keystore` and `setup` features are enabled. Host and keystore management remain available without `setup`.
- Validate feature combinations, including builds without default features. (#347)
